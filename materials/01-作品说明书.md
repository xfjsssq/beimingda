## 1. 一句话定位

**北民大小助手 ｜ 把散落的校园服务，收进一个对话。**

它不是一个"又一个校园 App"，而是**把校园服务能力做成 MCP 工具**、开放给任何支持 MCP 的 Agent（演示用 WorkBuddy）：
网页上有 6 个页面可以点，**不点网页也能只用一句话把事办完**。

---

## 2. 问题：校园服务散落在四个地方，谁也没把它们连起来

| 现状 | 学生的真实成本 |
|---|---|
| 取快递：群消息「谁帮我取一下」+ 私聊比价 | 靠人情、靠刷新群消息，**没有匹配机制** |
| 找搭子：树洞 / 群里发帖，留微信等着被加 | 先暴露身份才能筛人，**风险高、转化低** |
| 认路：纸质地图 / 问学长 / 高德搜"15 号楼" | 新生**到了楼下才知道长什么样** |
| 记 DDL：课表 + 备忘录 + 自己记 | 靠人脑，**漏一次就是一次损失** |

四件事分别散落在四个群里，**没有统一的入口，也没有可复用的能力层**。
本项目的判断是：与其再做第五个 App，不如**把这四件事做成一层可被 Agent 调用的能力**——
网页只是这层能力的一个可视化外壳。

## 3. 四个功能模块

每个模块都是「HTTP API + MCP 工具 + 独立页面」三件套，**HTTP 与 MCP 共用同一套 service 层**（不存在两份业务逻辑）。

### 3.1 代取撮合（M1）

- **解决什么**：把"谁帮我取快递"从人情请求变成**可打分的匹配**。
- **怎么用**：发布任务（取件楼栋 / 送达楼栋 / 截止时间 / 报酬区间）→ 引擎按**可达性 40 + 时段 30 + 报酬 30** 打分 → **只推得分 ≥ 60 的候选，最多 3 名**，同一跑腿者 5 分钟内不重复推送。
- **亮点一句**：**每个候选都带可解释理由**，且理由里的分值相加**正好等于** score（`reason: 可达 12号宿舍楼(+40)，时段完全覆盖(+30)，报酬 4 元 vs 下限 2 元(+30)` → 100 分）。
- **可核验点**：`POST /mcp` → `tools/call` `match_find_for_task`；`POST /api/tasks/:id/match`；表 `matches`；规则参数在 `config/match-rules.json`。

### 3.2 搭子匹配（M2）

- **解决什么**：想找一起自习 / 组队 / 运动的人，但**不想先暴露身份**。
- **怎么用**：一段大白话 → 服务端抽成结构化匿名画像（兴趣 / 作息 / 性格 / 期望 / 硬性要求 / 雷点）→ 按**兴趣 35 + 作息 30 + 性格 20 + 语义 15** 打分 → 只出 ≥ 60 分的候选；**双选揭示状态机**：双方都点头之前，返回里**完全不出现** `chat_ready` / `thread_id` 这两个键（不是返回 null）。
- **亮点一句**：候选只露 `anon_token`（随机生成、**不由 user_id 派生**），**先匹配、后同意、再站内开聊**（双方同意即开通站内私聊，不下发任何联系方式）。
- **可核验点**：`tools/call` `buddy_publish` / `buddy_search` / `buddy_consent`；表 `buddy_posts` / `buddy_consents`（`UNIQUE(post_id, seeker_id)` 保证一人一帖只表决一次）/ `threads` / `thread_messages`；双方同意后 `GET /api/threads` 能读到会话（非双方 → 明确报错，不是 404）。

### 3.3 迎新导览（M3）

- **解决什么**：新生"知道楼名，不知道长什么样、怎么走"。
- **怎么用**：校园底图 + 按分类（宿舍楼 / 食堂 / 教学与自习 / 校门 / 服务设施）打点 → 点标记看位置描述 → 已有实景的点位可进 **Pannellum 360° 查看器**（场景之间可互相跳转）。
- **亮点一句**：**底图零依赖、断网可跑**（手机地图截图 + 百分比坐标）；**没有实景的点位如实写"该点暂无实景"，绝不拿别的图糊弄**。
  本届提交的点位**暂无实景**（`pano/manifest.json` 的 `scenes` 为空），页面就是这么诚实地显示的——**不假装有实景**。
- **可核验点**：`tools/call` `map_list_nodes` / `map_get_node`；`GET /api/map/nodes`；表 `map_nodes`；底图配置 `static/map/map-bg.json`。

### 3.4 日程与提醒（M4）

- **解决什么**：课表和 DDL 记不住，但**又不愿意把姓名学号交给一个网站**。
- **怎么用**：课表**只能通过对话导入**（MCP `schedule_import`），平台只收 **6 个匿名字段**（周几 / 起止节次 / 课程名 / 教室 / 周次 / 提前提醒分钟）→ 周视图渲染 → 平台侧定时任务每 5 分钟扫一次，到点前触发提醒。
- **亮点一句**：**双层防御**（MCP schema 白名单 + service 层二次扫描），命中禁字段即丢弃并写**脱敏审计**——审计只记**字段名**、绝不记值，评委可 `GET /api/scrub/audit` 现场核验。
- **可核验点**：`tools/call` `schedule_import` / `schedule_add` / `schedule_query` / `schedule_remove`；表 `schedule_items` / `scrub_audit`；`scripts/reminder.js`；页面 `/schedule` 区块⑤。

## 4. MCP 可复用性：这是本作品与"又一个校园 App"的分界线

**结论先行：平台的全部能力不是页面按钮，而是 15 个 MCP 工具；页面只是这些工具的可视化外壳。
任何一个支持 MCP 的 Agent（WorkBuddy 或别家）都能零改造复用这层能力。**

### 4.1 接入形态：远程 URL 型，评委零安装

```json
{
  "mcpServers": {
    "beimingda": {
      "url": "https://demo.knowingly.dpdns.org/mcp",
      "headers": { "Authorization": "Bearer <DEMO_TOKEN>" }
    }
  }
}
```

- **传输**：**远程 Streamable HTTP**，端点 `POST /mcp`（⛔ 不做本地 stdio、⛔ 不用 SSE 长连接保活）。
- **拿配置**：站点 `/agent` 页 **一键复制**上面这段 JSON（令牌位置是占位符 `<DEMO_TOKEN>`，真实令牌由站长单独发给评委）。
- **四步接入**：打开 `~/.workbuddy/mcp.json` → 粘贴 → 重启 WorkBuddy → 连接器页点一次「信任」。

### 4.2 一句话就能操控整个平台

在 Agent 里说一句话，平台侧就是一次 `tools/call`：

| 你说 | 触发的工具 | 你得到 |
|---|---|---|
| 帮我发个代取，12 号楼取快递送到 15 号楼，今晚 8 点前，报酬 3 到 5 块 | `task_publish`（可选先 `task_parse_screenshot`） | 任务已发布 + 撮合候选与理由 |
| 我想找个一起自习的搭子，大二，工科，晚上比较有空 | `buddy_publish` → `buddy_search` | 匿名候选 + 分段得分 |
| 帮我看看 15 号楼在哪，有实景吗 | `map_get_node` | 节点详情 + 是否有实景 |
| 周三下午要交实验报告，提前两小时提醒我 | `schedule_add` | 提醒已排期 |

### 4.3 15 个工具（M1 5 / M2 3 / M3 2 / M4 4）

`task_parse_screenshot`、`task_publish`、`runner_register`、`match_find_for_task`、`task_list_open`、
`buddy_publish`、`buddy_search`、`buddy_consent`、
`map_list_nodes`、`map_get_node`、
`schedule_import`、`schedule_add`、`schedule_query`、`schedule_remove`

> 核验方式（评委可现场复现）：
> `POST /mcp` + `{"jsonrpc":"2.0","id":1,"method":"tools/list"}`（带 `Authorization: Bearer <DEMO_TOKEN>`）→ 返回 **15** 个工具；
> `/agent` 页区块⑤ 也会**实时**显示"POST /mcp tools/list 返回 15 个工具，与下方清单完全一致 ✓"。

### 4.4 为什么这层能力是可复用的（不是项目私有代码）

1. **工具契约与业务实现分离**：工具 schema 在 `src/mcp/tools.js` 统一注册，处理器在 `src/mcp/handlers/*.js`，业务在 `src/services/*`、算法在 `src/engine/*`——
   **换一个前端、甚至不要前端，这层能力照样跑**。
2. **所有工具 `additionalProperties: false`**：多传一个字段直接 `SCHEMA_REJECTED`，**不给 LLM 编参数的机会**（对 Agent 友好）。
3. **统一返回信封** `{ok, data, error}` + 固定错误码（`SCHEMA_REJECTED` / `NOT_FOUND` / `TIMEOUT` / `QUOTA` / `INTERNAL`）：
   Agent 不需要为每个工具写一套解析逻辑。
4. **失败可自纠**：例如发布任务时楼栋名不合法，返回 `SCHEMA_REJECTED` 并**列出可选规范名**（如"未知楼栋「火星楼」。可选：12号宿舍楼/15号宿舍楼/…"），Agent 能据此重试而非死循环。
5. **同源**：`npm run verify` 会**自动发现已注册工具并逐个真调**（15 个工具 × 参数校验 + 越权字段守卫），页面与 MCP 不会各说一套。

**一句话**：这 15 个工具就是"北民大小助手"作为**平台**对外暴露的能力接口；页面是消费者之一，WorkBuddy 是另一个消费者。

## 6. 合规声明（与 `04-合规与隐私说明.md` 同一口径）

1. **不收集身份信息**：全站不收集真实姓名 / 学号 / 手机号 / 证件号 / 学生证照片 / 校内系统口令；
   数据库**没有任何字段能存这些**（`users` 表只有 `handle` 昵称、登录用的口令哈希 `pass_hash`/`pass_salt`，
   以及一个**已废弃的历史列** `contact_code`——旧"中转码"机制的遗留，接口不再输出、新流程不再使用）。
2. **不接入学校任何内部系统**：不接入、不登录、不抓取；全站没有"输入学号 / 校内口令"的字段或方案。
3. **站内没有任何文件上传控件**（刻意设计）：课表入口只能走对话（MCP），服务端**没有**课表文件上传接口；
   代取截图也**不在站内上传**（2026-10-31 起下线）——需要识别时请在 WorkBuddy 里把截图发给对话方，
   由 MCP `task_parse_screenshot` 当场理解，**图片不落服务器磁盘**。
4. **只收白名单字段**：日程只允许 6 个匿名字段（`weekday / period_start / period_end / title / room / weeks`），
   MCP schema + service 层**双层防御**；命中禁字段即丢弃并写**脱敏审计**（只记字段名、不记值，可 `GET /api/scrub/audit` 核验）。
5. **演示数据全匿名**：`?demo=1` 下姓名一律显示为「同学A / 同学B」，页面右上角有「演示模式」徽章；
   材料与录屏中的令牌一律写作占位符 `<DEMO_TOKEN>`。
6. **平台不参与交易**：代取报酬由双方线下协商，平台不代收款、不承诺履约。

## 8. 已知边界（如实写在材料里，不粉饰）

1. **LLM 能力默认关闭**：`.env` 里 `LLM_*` 未配置时，M1 的截图字段理解与 M2 的语义 15 分走**规则化降级实现**
   ——功能不阻塞，**精度下降**（有 key 时自动走模型）。
2. **M2 契约标题里的"11 字段"是概数**：以 `contracts/m2-buddy.md` §1 的 JSON 结构为权威（9 个顶层键 / 13 个叶子字段）。
3. **M2 "先表决后搜索"时两处分数口径不同**：`buddy_consents.score`（表决时算）与候选列表同一条的 `score`（当次搜索算）可能不一致；
   **是否揭示只由双选状态机决定**，与分数无关（契约里表决接口即不收画像，属固有差异）。
4. **楼栋名"先归一、归一失败再拒"**：`12号楼` / `15栋` / `菜鸟驿站` 会自动折成规范名；折不出来就 `SCHEMA_REJECTED` 并列出可选规范名
   ——比"硬造一个不存在的楼、让任务永远匹配不到人"更诚实。
5. **M3 底图与全景是人工素材**：当前 `pano/manifest.json` 的 `scenes` 为空（**实景 0 个**），底图也是占位示意图；
   页面**如实提示**"该点暂无实景" / "占位示意底图"，**不拿别的图冒充实景**。
   已有实景素材的点位可进 360° 查看器（Pannellum 已本地化、hotSpot 互跳已实现），补齐图片即可用。
6. **地图服务**：不申请任何在线地图瓦片服务（理由见 `02-技术方案.md` §1）；联网时会话可选高德卫星图增强，
   底图本身是离线截图，**断网也能演示**。
