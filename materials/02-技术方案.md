## 1. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | **静态 HTML + 原生 JS（零构建）** | 无打包器、无 Node 运行时依赖，`npm start` 即可；共用 `static/css/app.css` + `static/js/api.js`/`nav.js`/`demo.js` |
| 地图 | **手机地图截图底图 + 百分比坐标**（离线可跑） | 底图 `static/map/campus-map.*`，点位坐标在 `static/map/map-bg.json`；**联网可选增强**：高德 JS API 可拖动卫星图 + 高德官方嵌入 iframe（零 key 降级视图）。⚠️ 增强视图需 `map_nodes.lat/lng` 已录入，当前仍是占位 `0` → 增强视图只显示校园中心并提示"点位坐标待录入"（**不猜位置**） |
| 全景 | **Pannellum**（MIT，已本地化到 `static/vendor/pannellum/`，含 COPYING） | 纯前端 multi-scene tour，`hotSpots` 实现场景互跳 |
| 后端 | **Node.js 20+ / Express 4 / better-sqlite3** | 单进程、单文件 SQLite，零外部服务 |
| MCP | **远程 Streamable HTTP**，端点 `POST /mcp` | ⛔ 不做本地 stdio；⛔ 不用 SSE 长连接 |
| 部署 | Cloudflare 隧道 → `https://demo.knowingly.dpdns.org` | 健康检查 `GET /api/health` 供隧道看门狗探测 |

**为什么地图不申请在线地图服务（一句话）**：截图底图**零申请、零 key、零外部依赖、断网可跑**，而路演与直播的演示场景只有一栋校园、几栋楼，
**不需要在线瓦片**；在线地图只作为联网时的增强选项（高德），加载失败自动回落到截图底图，页面不白屏。

> 注：早期方案曾计划「Leaflet + 在线瓦片」，因"申请 key 的收益不抵其不确定性"已作废（`contracts/m3-welcome.md` 2026-10-27 修订）。
> 因此现在**没有任何地图 key 是必需的**；`/config.js` 里预留的注入点仅用于可选增强。

**一次 MCP 工具调用的生命周期**（以 `task_publish` 为例）：

```
WorkBuddy 对话
  → POST /mcp  Authorization: Bearer <DEMO_TOKEN>
  → middleware/auth.js（定长比较，兼容不带 Bearer 前缀）
  → JSON-RPC 解析 → tools/call → middleware/ratelimit.js（工具 30 次/分钟）
  → src/mcp/tools.js::validateArgs（required + additionalProperties:false）
  → src/mcp/handlers/takeout.js → src/services/task.js → src/engine/match.js → src/db
  → 统一信封 {ok,data,error} → 同时放进 result.structuredContent 与 content[0].text
  → 单请求单响应返回（无 SSE、无长连接，单次 < 90 秒）
```

## 3. 数据库：9 张表

| 表 | 用途 | 设计意图（一句话） |
|---|---|---|
| `users` | 用户 | 只有 `handle` 昵称与可选 `contact_code`，**没有任何身份字段** |
| `tasks` | 代取任务 | 楼栋路径 + 截止时间 + 报酬区间；`screenshot_path` 可空，截图本身不落库 |
| `runners` | 跑腿方能力 | 可达楼栋（JSON）、报酬下限、可用时段（JSON）；`user_id` UNIQUE → 重复登记即覆盖 |
| `matches` | 撮合记录 | 存 `score` 与 `state`，支撑"引擎真的在算"与推送去重 |
| `buddy_posts` | 搭子帖（匿名） | 只存 `anon_token`（随机）+ 结构化 `profile_json`，不存身份 |
| `buddy_consents` | 双选表决 | `UNIQUE(post_id, seeker_id)` → 一人一帖只能表决一次（数据库层硬保证） |
| `schedule_items` | 日程 | 只收 6 类匿名字段（周几 / 起止节次 / 课程名 / 教室 / 周次 / 提醒分钟） |
| `map_nodes` | 地图节点 | 节点名 + 分类 + 经纬度（可选）+ 全景路径（可为空表示暂无实景） |
| `scrub_audit` | **脱敏审计** | **只记被丢弃的字段名，绝不记字段值**（`dropped_fields` 是 JSON 数组） |

**索引与约束（不是可选项）**

- `idx_tasks_status_deadline ON tasks(raw_status, deadline_ts)` —— 开放任务看板与撮合查询走它（"open 且未过期"一次命中）；
- `idx_matches_task ON matches(task_id, score DESC)` —— 按任务取候选并按分排序；
- `idx_sched_user_weekday ON schedule_items(user_id, weekday, period_start)` —— 周视图按"人 + 周几 + 节次"直出；
- 约束：`runners.user_id UNIQUE`（一人一份跑腿能力）、`buddy_posts.anon_token UNIQUE`、`buddy_consents.UNIQUE(post_id, seeker_id)`；
- `PRAGMA foreign_keys = ON`（外键全开，删帖/删任务不留孤儿行）。

**时间口径**：库内统一 **Unix 秒 INTEGER**，出接口统一 **ISO 8601 带时区**，转换封装在 `src/util/time.js`——避免各模块各写一套时区逻辑。

**补充（三条写进评审要点）**

1. 所有工具 schema 都是 `additionalProperties: false` —— **多传一个字段即 `SCHEMA_REJECTED`**（`npm run verify` 对 14 个工具逐一实测这条）。
2. MCP 与 HTTP API **共用同一套 service 层**，不存在两份业务逻辑。
3. 接入方式是**远程 URL 型**（`POST /mcp`），不是本地 stdio —— **评委零安装、零配置**即可连。

## 5. 三条不可违反的技术约束（本项目的工程取舍）

1. **不做本地 stdio MCP**：评委必须零配置接入，只能远程 URL 型。stdio 方案要求评委在本机装 Node、配路径、跑进程，**与"零门槛"矛盾**。
2. **CF 隧道 100 秒硬限制**：MCP 端点是**短请求 + 单响应**，**不用 SSE 长连接保活**，任何单次响应 < 90 秒。
   这也是提醒机制用**平台侧定时任务**（`scripts/reminder.js`，每 5 分钟）而不是长连接推送的原因。
3. **所有密钥只从 `process.env` 读**：`DEMO_TOKEN`、可选的 LLM key、可选的高德 key 一律环境变量注入
   （页面侧经 `/config.js` 运行时注入，**页面里不硬编码**）；`npm run smoke` 有一项专门扫描"全仓无硬编码密钥"。

## 6. 关键实现

### 6.1 撮合评分（M1）：权重固定，理由可加验

```
可达性 40：命中送达楼 +40 / 仅命中取件楼 +20 / 都不命中 → 出局
时段   30：完全覆盖 [now, deadline] +30 / 重叠 ≥50% +20 / <50% +10 / 不重叠 → 出局
报酬   30：clamp((reward_max − runner.reward_floor) / (reward_max − reward_min), 0, 1) × 30
总分 = 三项之和（0~100）；推送阈值 60；单任务最多推 3 人；同一人 5 分钟内不重复推送
```

- 权重与阈值只放在 `config/match-rules.json`（**只放参数，不改语义**）。
- `reason` 里的分值按"分"（×100 取整）相加，**严格等于** `score`；实测举例：
  `可达 12号宿舍楼(+40)，时段完全覆盖(+30)，报酬 4 元 vs 下限 2 元(+30)` → **100 / 100**。
- 推送去重：同 `(task, runner)` 300 秒内不重复写 `matches`（`state='pushed'`）。

### 6.2 搭子评分 + 双选状态机（M2）

```
一票否决：seeker.must_have 与 post.deal_breaker 语义冲突 → 0；kind 不一致 → 出局
兴趣 35（Jaccard） + 作息 30（Δearly_bird / Δweekend_free / busy_slots 冲突罚分）
+ 性格 20（三维欧氏距离归一） + 语义 15 → 阈值 60
```

- 双选状态机（`src/engine/doubleOpt.js`）：初始 `author_ok=0, seeker_ok=0, revealed=0` →
  任一方同意只置自己那一位 → **双方都为 1 才 `revealed=1` 并吐 `contact_code`**。
- **出口以状态机推导为准**：即使库里 `revealed` 被写成脏值，只要 `author_ok && seeker_ok` 不成立，返回里就没有 `contact_code` 键（有专项测试）。
- 冲突判定补了"同主题反义立场"识别（如 `希望安静` vs `讨厌安静` 判冲突；`希望安静` vs `安静` 不判冲突），并有断言防误否决回归。

### 6.3 楼栋名归一（M1，Agent 友好性）

`task_publish` / `runner_register` 会先把楼栋名折成 `config/map-nodes.json` 的**规范名**
（`12号楼` / `12栋` / `十二号宿舍楼` → `12号宿舍楼`；`菜鸟驿站` → `快递驿站`），
**折不出来就 `SCHEMA_REJECTED` 并在 message 里列出可选规范名**，让 Agent 自我纠正。
MCP 与 HTTP **共用同一套归一实现**（`src/services/task.js`），不各写一份。

### 6.4 课表双层防御 + 脱敏审计（M4）

```
第 1 层 MCP schema：items 只列 6 个白名单字段 + additionalProperties:false
                   → 多传 studentNo → SCHEMA_REJECTED（不进 service）
第 2 层 service：src/services/scrub.js 逐字段扫描黑名单（name/realName/studentNo/.../idCard）
                   → 命中即丢弃该字段，只把字段名写进 scrub_audit
另：title 里夹带的教师姓名会被剥离（剥离内容不写日志、不写审计）
```

实测（评委可复现）：

```bash
GET  /api/scrub/audit?limit=5
→ {"ok":true,"data":[{"id":1,"item_type":"schedule",
    "dropped_fields":["studentNo","phone"],"created_at":"..."}]}
```

**审计里只有字段名，没有任何值** —— 这是本模块最硬的一条合规证据。

### 6.5 演示与离线

- `GET /api/demo/seed` **幂等**灌入 fixtures，并"热身"撮合（让首页"平均匹配得分"开箱有真实数字，分数由真引擎算出，不是编的）。
- `?demo=1`：显示「演示模式」徽章、姓名映射为「同学A / 同学B」、并按兜底规则打码学号/手机号形态的字符串。
- 第三方库全部本地化（`static/vendor/pannellum/` 含 COPYING），**无外部 CDN**；`npm run verify` 有一项专门扫"static 里没有指向外部第三方站点的资源依赖"。
- 底图是本地图片 + 本地 JSON 坐标 → **断网可跑**。
- **实测（截图时同步复核）**：`/welcome` **12 个点位**全部渲染；6 页 375px 视口 `documentElement.scrollWidth === 375`（不破版）；
  6 页 `?demo=1` 徽章均可见；页面**零 4xx 噪音**（缺 `favicon.svg` 的 404 已补齐）。

## 7. 已知边界与取舍（评委常问的"为什么不做 X"）

| 不做 | 为什么 |
|---|---|
| 本地 stdio MCP | 与"评委零配置"矛盾（见 §5-1） |
| SSE 长连接 / WebSocket 推送 | CF 隧道 100 秒硬限制；提醒改用平台侧定时任务 |
| 自建或申请在线地图瓦片 | 演示场景不需要在线瓦片；截图底图零依赖、断网可跑 |
| 课表**文件上传**接口 | 刻意设计：文件里有姓名学号，**让文件留在用户设备**，只让 6 个字段进平台 |
| 平台代收款 / 承诺履约 | 平台不参与交易，报酬双方线下协商 |
| 把照片纳入搭子评分 | 隐私与公平；照片不参与评分（页面也不提供上传） |

**其他如实记录的限制**

1. `LLM_*` 未配置时：M1 截图理解、M2 语义 15 分走**规则化降级实现**（功能不阻塞、精度下降）。
2. M2 契约标题的"11 字段"是概数，权威是 §1 的 JSON 结构（9 顶层键 / 13 叶子）。
3. M2 "先表决后搜索"时表决落库分与候选分口径不同（是否揭示只由状态机决定）。
4. M3 底图/全景是人工素材：`pano/manifest.json` 的 `scenes` 当前为空（**实景 0 个**），底图为占位示意图；
   页面如实提示"该点暂无实景"/"占位示意底图"，**不拿别的图冒充实景**。
   高德 JS API 增强视图当前不产出交付截图：本机调试时有 key 但域名白名单不含 `127.0.0.1`（返回 `INVALID_USER_DOMAIN/10006`），
   演示域名侧环境变量未配置该 key；且 `map_nodes.lat/lng` 仍为占位 `0`，增强视图无法落我们的点位——**如实记录，不硬凑**。

## 8. 可复用性小结

这 14 个工具是**平台能力接口**，不是某个前端的私有函数：

- **换前端不受影响**：页面只是消费者，删掉 `static/` 后 MCP 与 HTTP API 照常工作；
- **换 Agent 不受影响**：任何支持 MCP 的客户端都能连（`POST /mcp` + Bearer 令牌）；
- **契约稳定**：`additionalProperties:false` + 统一信封 + 固定错误码，Agent 侧无需为每个工具写解析器；
- **可自纠**：错误信息里带"可选值清单"（如楼栋规范名），Agent 能据此重试。
