## 1. 不收集身份信息 —— 数据库层就不给这个可能

**做法**：从建表那一刻起，**没有任何列能存**真实姓名 / 学号 / 手机号 / 证件号 / 学生证照片。
唯一与"人"相关的列是 `users.handle`（**昵称字符串**，演示里就是"同学A"）与登录用的口令哈希 `pass_hash` / `pass_salt`（**不可逆、只用于本人登录**）。
另有历史列 `users.contact_code`：那是**已废弃的旧"中转码"机制**留下的列——**保留在库里仅为兼容老数据，接口不再输出、新流程也不再使用**
（双方同意后改为站内私聊，不再下发任何联系方式）。它不是手机号，也不含任何身份信息。

**可核验位置**

1. **表结构**：`src/db/schema.sql`（13 张表）。逐列看，`users` 只有
   `id / handle / contact_code（历史遗留，已废弃不对外） / pass_hash / pass_salt / created_at / demo`。
2. **命令**（评委可照跑）：
   ```bash
   npm run smoke     # 有一项：schema.sql 表清单与 contracts/core.md §2 一致（13 张表）
   ```
3. **接口**：`GET /api/buddies` 只暴露 `anon_token` 与结构化画像，**不含 `user_id`**；`buddy_search` 的返回里
   院系全名 / 班级 / 学号 / 宿舍号 / 真实姓名 / 联系方式**一律不出现**（`npm run verify` 对工具逐个真调）。
4. **照片**：搭子页**没有**照片上传控件（`input[type=file]` 在该页数量为 0），照片也不参与评分。

**为什么这条能"证明"而不是"承诺"**：字段不存在 → 想收集也存不进去；这比在页面上写一句"我们不会收集您的信息"更硬。

## 2. 不接入学校任何内部系统

**做法**：没有对接、没有登录、没有抓取。全站业务代码里**不存在**"输入学号 / 校内口令"的字段或方案。

**可核验位置**

1. **代码扫描**（应无输出）：
   ```powershell
   Get-ChildItem -Recurse src,static -Include *.js,*.html | Select-String -Pattern 'input[^>]*student|学号登录|edu\.cn/.*login|campus-account'
   ```
2. **鉴权只有一种**：`src/middleware/auth.js` —— 只校验演示令牌（`DEMO_TOKEN`，从环境变量读），**没有任何第三方登录态**。
3. **入口清单**：`src/api/routes.js` 里挂的路由全部是本平台自有数据（任务 / 搭子 / 日程 / 地图节点 / 审计），**没有一条转发到外部系统**。
4. **依赖清单**：`package.json` 只有 `express` 与 `better-sqlite3` 两个运行依赖，**没有爬虫/自动化登录类库**。

## 3. 站点没有「上传课表文件」的按钮 —— 这是刻意设计

**做法**：课表的唯一入口是**对话**（MCP `schedule_import` / `schedule_add`）。
服务端**不提供**任何课表文件上传接口；页面上也**没有**课件上传控件。
理由：课表文件里有姓名、学号，**让文件留在用户自己的设备上**，只让 6 个字段进平台。

**可核验位置**

1. **按钮**：`/schedule` 页区块②明写"课表文件**不要上传到这里**，本页面没有、也不会有任何上传入口"（页面实拍见 `截图清单.md` 图 7）。
2. **控件扫描**（应**全站 0 处**——代取截图入口已于 2026-10-31 下线）：
   ```powershell
   Get-ChildItem -Recurse static -Include *.html | Select-String -Pattern 'type="file"'
   # → 无输出（0 处；课表页 0 处，代取页也已下线）
   ```
3. **接口扫描**（应无输出）：
   ```powershell
   Get-ChildItem -Recurse src -Include *.js | Select-String -Pattern 'multer|/upload'
   # → 无
   ```
4. **契约层固定**：`contracts/m4-schedule.md` §6 标注"本模块不提供 `POST /api/schedule/upload` 这类文件上传接口。**刻意不做**"。

> **站内没有任何文件选择入口**（2026-10-31 起代取截图上传也下线了）：需要识别取件截图时，
> 请**在 WorkBuddy 里把截图直接发给对话方**，由 MCP 工具 `task_parse_screenshot` 当场理解
> （base64 只在该次请求内使用 → **不写服务器磁盘**；⛔ 不抽取姓名 / 手机号 / 运单号）。
> 站内发布表单只有文字字段，`screenshot_path` 恒为 `null`，任务照常发布。

## 4. 课表字段白名单 + 双层防御

**白名单只有 6 个字段**：`weekday` / `period_start` / `period_end` / `title` / `room` / `weeks`（提醒提前量 `remind_before` 由用户在本站设置）。
**黑名单**（命中即丢弃）：`name`、`realName`、`studentNo`、`studentId`、`stuNo`、`teacher`、`teacherName`、`className`、`major`、`college`、`grade`、`score`、`gpa`、`rank`、`phone`、`mobile`、`idCard`。

**双层防御（缺一不可）**

| 层 | 位置 | 行为 | 实测证据 |
|---|---|---|---|
| 第 1 层 | `src/mcp/handlers/schedule.js` 的 `items` schema（`additionalProperties: false`） | 多传任何字段 → `SCHEMA_REJECTED`，**根本不进 service** | `schedule_import` 传 `studentNo` → `SCHEMA_REJECTED: items 含非法字段: studentNo,phone,real_name` |
| 第 2 层 | `src/services/scrub.js`（白名单 + 黑名单 + title 去人名） | 即使绕过 schema（如 HTTP 直调），逐字段扫描，命中即丢弃并写审计 | `POST /api/schedule` 带 `studentNo/phone` → 写入成功但**这两个字段被丢弃**，`scrub_audit` 新增一条 |

**额外一条**：`title` 里夹带的教师姓名会在写入前被剥离（`sanitizeTitle`），**被剥掉的内容不写日志、不写审计**。

**可核验命令**

```bash
npm test        # M4 用例含：多传 studentNo → SCHEMA_REJECTED；service 层独立拦；区间倒挂 → SCHEMA_REJECTED；重复导入不叠加
```

## 5. 令牌：只从环境变量读、限频、材料里一律占位符

**做法**

- `DEMO_TOKEN` **只从 `process.env` 读**（`src/middleware/auth.js::demoToken()`），**代码里零硬编码**。
- 比较用**定长比较**（`crypto.timingSafeEqual`），避免时序侧信道。
- 端点与限频：**HTTP API 单 IP 60 次/分钟**；**MCP 工具调用 30 次/分钟**。
- MCP 端点：`Authorization: Bearer <DEMO_TOKEN>`（兼容不带 `Bearer ` 前缀）；HTTP 写接口：`X-Demo-Token` 头。
- **令牌进入任何材料、页面、截图、录屏时一律写作占位符 `<DEMO_TOKEN>`**；真实值只存在于服务端环境变量，由站长单独发给评委。

**可核验位置**

1. **代码**：`src/middleware/auth.js`（令牌只读环境变量）、`src/middleware/ratelimit.js`（限频）。
2. **命令**（应无输出 = 全仓无硬编码密钥）：
   ```bash
   npm run smoke   # 其中一项「全仓无硬编码密钥」
   ```
3. **页面**：`/agent` 页的一键复制 JSON 里令牌位置**永远是 `<DEMO_TOKEN>`**（`static/js/mcp-config.js` 的 `TOKEN_PLACEHOLDER`）；
   页面上也不回显真实令牌值。
4. **仓库**：真实令牌不在仓库任何受版本控制的文件里（只在被 `.gitignore` 忽略的 `.env`）。

**如实说明（不粉饰）**：演示令牌为**赛事演示用途**，它可调用 MCP 工具，也可调用站点的**演示写接口**（发布任务 / 发帖 / 加载日程），
因此我们按"**限频 + 短周期轮换 + 只能写演示数据**"来控制风险，而不是宣称"绝对不可能写入"。
令牌泄露的后果上限是"别人在你的演示库里发几条虚构任务"，**不涉及任何身份信息**。

## 6. 脱敏审计：只记字段名、绝不记值，且对外可查

**做法**：每次导入后被丢弃的字段，写入 `scrub_audit(item_type, dropped_fields, created_at)`，
`dropped_fields` 是**字段名组成的 JSON 数组**——**不写任何字段值，一个字符都不写**。

**可核验位置**

1. **接口**：`GET /api/scrub/audit?limit=5`（只读，开放，无需令牌）。
2. **实测返回**（本次自检真实输出）：
   ```json
   {"ok":true,"data":[{"id":1,"item_type":"schedule",
     "dropped_fields":["studentNo","phone"],
     "created_at":"2026-10-27T13:34:05.000Z"}]}
   ```
   —— 只有**字段名** `studentNo` / `phone`，没有任何值。
3. **页面**：`/schedule` 页区块⑤「脱敏审计」，表格列只有「时间 / 类型 / 被丢弃的字段名」，下方一句"审计只记录字段名，绝不记录任何字段值"。
4. **代码**：`src/services/scrub.js::writeAudit()`（只接受字段名数组，且去重后才写库）。
5. **Agent 侧的合规义务**：`schedule_import` 返回 `{imported, dropped_fields}`，
   Agent 每次导入后必须向用户汇报"写入了多少条、丢弃了哪些类别的字段"（`/agent` 页与演示脚本都有这句）。

## 7. 演示数据全匿名

**做法**：`?demo=1` 时 —— ① 页面右上角显示「**演示模式**」徽章；② 姓名映射为「同学A / 同学B / 同学C…」；
③ 对学号/手机号形态的字符串做**兜底打码**（本来也不该出现，这是第二道防线）。
全部演示数据来自 `fixtures/`（**全虚构**）与 `GET /api/demo/seed`（**幂等**）。

**可核验位置**

1. **实测**（375×812，`?demo=1`）：6 个页面「演示模式」徽章**均可见**，且 `documentElement.scrollWidth === 375`（无横向溢出）。
2. **fixtures**：`fixtures/tasks.json` / `runners.json` / `buddy-posts.json` / `schedule.json` 里的人名只有「同学A / 同学B / 同学C」。
3. **代码**：`static/js/demo.js`（徽章 + 假名映射 + 兜底打码规则）。
4. **数据标注**：首页统计区下方明写"以下数字由 `GET /api/demo/seed` 灌入的虚构演示数据统计而来，不对应任何真实的人或事"。
