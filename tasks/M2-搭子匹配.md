## 关键实现要点

### 一票否决必须用 LLM 做语义判断
不要用字符串相等。例：
```js
// post.deal_breaker = ["凌晨打游戏外放"]
// seeker.must_have  = ["室友必须安静，不能半夜吵"]
// 字符串不相等，但语义冲突 → 必须判为冲突
```
用一次 LLM 调用做批量冲突判定，返回冲突对列表。

### anon_token 生成（关键：不可由 user_id 派生）
```js
import crypto from "node:crypto";
const anonToken = () => "anon_" + crypto.randomBytes(6).toString("hex"); // 12 位
```
⛔ 不许用 `hash(user_id)`、`user_id.slice()` 之类可反推的方式。

### 双选状态机（单独文件，逻辑要清晰到评审一眼看懂）
```js
// engine/doubleOpt.js
export function applyConsent(row, who, agree) {
  const next = { ...row };
  if (who === "seeker") next.seeker_ok = agree ? 1 : 0;
  if (who === "author") next.author_ok = agree ? 1 : 0;
  next.revealed = (next.author_ok === 1 && next.seeker_ok === 1) ? 1 : 0;
  return next;
}

// 返回给调用方时：
export function toResponse(next, contactCode) {
  const base = {
    author_ok: next.author_ok,
    seeker_ok: next.seeker_ok,
    revealed: next.revealed,
  };
  // ⛔ 关键：revealed=0 时 contact_code 这个键根本不出现在对象里
  if (next.revealed === 1) base.contact_code = contactCode;
  return base;
}
```

### 候选结果必须过滤可反推身份的字段
```js
// 从 buddy_posts 取数据后，只允许透出这些字段
const safe = (p) => ({
  anon_token:    p.anon_token,
  score:         p.score,
  reason:        p.reason,
  reveal_status: p.reveal_status,
  kind:          p.kind,
  // ⛔ 不含 author_id / user_id / 院系全名 / 班级 / 学号 / 宿舍号
});
```
