# 怎么补 360° 全景素材（M3 · 保姆级 SOP）

> **现状**：代码路径已全部就绪（Pannellum 已本地化到 `static/vendor/pannellum/`，
> `welcome.html` 点标记 → 有实景就开 360°、没实景就如实提示），**当前 0 张实景，只等素材**。
> 本文件就是"以后怎么把照片补进来"的操作手册 —— 半张图都不用改代码。

---

## 一、先搞清一件事：Pannellum 不吃"几张照片"，它吃**一张等距柱状图**

Pannellum 不是"把多张照片拼起来"的工具，它需要一个**已经处理好的全景图文件**：

| 类型 | 说明 | 我们要用的 |
|---|---|---|
| **equirectangular（等距柱状）** | 一张 2:1 的图（宽 = 2 × 高）。相当于把地球仪展开成平面 | ✅ **就用这个** |
| cubemap | 6 张正对的照片（前后左右上下） | 需要三脚架+专业相机，不划算 |
| multires | 超大图切成瓦片，要跑 Pannellum 自带脚本 | 图特别大时才需要 |

**关键点：如果你用手机自带的「全景模式」拍，手机在机内就已经帮你缝合好了，直接输出一张等距柱状图** ——
你**完全不需要**额外的缝合工具。这是最省事的路，也是推荐的路。

---

## 二、三条拿图路线（按省事程度排）

### 路线 A · 手机全景模式（推荐，每个点位约 1 分钟）

1. 打开相机 → **全景 / 全景模式**（多数安卓机在"更多"里，iPhone 直接左滑到 Pano）
2. **手机横屏**，用竖屏方向拍：把手机**竖直拿稳**，绕自己身体**水平匀速**转一圈
3. 从起点开始 → **转回起点**再松手（Pannellum 的接缝在这一圈闭合处）
4. 拍完回看两张东西：**地平线是否平**、**首尾接缝处有没有明显断线**

### 路线 B · 多张照片自己缝合（只有在 A 拍不出来时才用）

| 工具 | 平台 | 费用 |
|---|---|---|
| **Hugin** | Win/macOS/Linux | 免费开源，首选 |
| PTGui | Win/macOS | 付费 |
| Photoshop → Photomerge | Win/macOS | 有 PS 就用它 |
| 手机 App（如 Panorama 360、Google 相机） | Android/iOS | 免费 |

缝合目标同样是：**一张 2:1 的等距柱状图**（导出时选 *equirectangular* 投影）。
拍素材时每张相邻照片**重叠 30% 以上**，方便算法对齐。

### 路线 C · 不拍（完全合法）

`config/map-nodes.json` 里 `pano_url` 保持 `null`，页面会如实显示
「该点暂无实景，以下是位置描述」。**契约本来就允许这样**，不算未完成，
只是演示时少一个亮点。（⛔ 千万别拿网图冒充本校实景 —— 那是契约明令禁止的。）

## 三、"确定是 360 度吗？" —— 两个判断标准 + 一个实用技巧

### 1. 看尺寸比例
完整的球面 = 水平 360° × 垂直 180°，所以标准等距柱状图是 **2:1**。
看到 `6000×3000`、`4096×2048` 这类就是标准的。

### 2. 手机全景通常**不是**完整 180° 垂直
手机全景模式一般只覆盖**水平 360°、垂直 60°~80°**（上下没拍）。这也能用，
只要告诉 Pannellum 实际覆盖多少：在 `manifest.json` 的场景里加这几个参数：

```json
{
  "type": "equirectangular",
  "panorama": "/pano/dorm-12.jpg",
  "haov": 360,      // 水平实际覆盖（手机全景基本都是 360）
  "vaov": 70,       // 垂直实际覆盖（按你拍到的角度填，如 60~80）
  "vOffset": 0,     // 画面中心相对赤道的偏移，画面偏上就填正数
  "hfov": 100,      // 打开时的初始视野宽度
  "minPitch": -30,  // 限制上下视角，避免转到没拍到的黑洞区域
  "maxPitch": 30,
  "backgroundColor": "#222222",   // 万一露出边缘，用深灰兜住
  "autoRotate": -2                // 可选：自动慢速旋转，演示时更抓眼
}
```

所以答案是：**手机拍的那张算不算"360 度"取决于你要什么** ——
水平一圈是 360°（够用，能环视），垂直不是 180°（上下会有边界）。
用 `vaov`/`minPitch`/`maxPitch` 把视角限制在实际拍到的范围内，看起来就是完整的一圈，不会穿帮。

### 3. 接缝自检
把图丢进 <https://pannellum.org/> 官方在线 demo 或本地 `static/vendor/pannellum/pannellum.htm`，
转一圈看首尾接缝有没有明显错位 —— 比肉眼猜可靠。

## 四、落地到项目（4 步，改的都是数据文件，不用动代码）

1. **放图**：文件名 = 节点 id，例如 `pano/dorm-12.jpg`（id 见 `config/map-nodes.json`）
2. **压缩**：单张 **≤2MB**、宽度 4000~6000px（宽 = 2 × 高）
   ```bash
   # ImageMagick
   magick in.jpg -resize 6000x3000 -quality 82 pano/dorm-12.jpg
   # 或者用网页工具 Squoosh（拖进去 → 导出 JPEG → 质量 80 左右）
   ```
3. **登记**（两处，改完刷新页面即可，**不用重启服务**）：
   - `config/map-nodes.json`：把该节点的 `pano_url` 改成 `"/pano/dorm-12.jpg"`，
     `pano_yaw` 填初始朝向（0 = 北，顺时针度数）
   - `pano/manifest.json`：在 `scenes` 里加一个场景（模板见下）
4. **验证**：打开 `/welcome` → 点该点位 → 出现「查看 360° 实景」→ 能拖拽环视 → 手机也能拖

### `pano/manifest.json` 场景模板（照抄改）

```json
{
  "default": { "firstScene": "dorm-12", "sceneFadeDuration": 800 },
  "scenes": {
    "dorm-12": {
      "title": "12号宿舍楼 · 楼下快递驿站",
      "type": "equirectangular",
      "panorama": "/pano/dorm-12.jpg",
      "yaw": 180,
      "pitch": 0,
      "haov": 360,
      "vaov": 70,
      "hfov": 100,
      "minPitch": -25,
      "maxPitch": 25,
      "backgroundColor": "#222222",
      "hotSpots": [
        { "pitch": -5, "yaw": 90, "type": "scene", "text": "去往第二食堂", "sceneId": "canteen-2" },
        { "pitch": 0, "yaw": 270, "type": "info", "text": "快递驿站入口在右手边" }
      ]
    },
    "canteen-2": {
      "title": "第二食堂 · 正门",
      "type": "equirectangular",
      "panorama": "/pano/canteen-2.jpg",
      "yaw": 0,
      "hfov": 100,
      "hotSpots": [
        { "pitch": -5, "yaw": 270, "type": "scene", "text": "回 12 号楼", "sceneId": "dorm-12" }
      ]
    }
  }
}
```

> ⭐ `hotSpots` 里 `"type": "scene"` 就是"点击地面箭头跳到另一个点位"，
> 两个点位**互相加一条**就能来回跳。这是演示时最出效果的地方（30 秒能拍完两个点位，互相跳一次）。

## 五、仓库体积纪律

| 情况 | 做法 |
|---|---|
| 全景素材总量 ≤ 20MB | 直接提交进仓库（每张 ≤2MB） |
| 20–50MB | 只提交 3–4 个点位的图，其余留 `null` |
| > 50MB | 别进仓库：放外部云盘，另写一个 `pano/README-DOWNLOAD.md` 说明下载方式 |

拍摄时**不要**把人脸、车牌、门牌号拍进去；拍到了就打码或重拍（契约硬要求）。
